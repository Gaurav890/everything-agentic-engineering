# Design-system audit

Compare documented intent, canonical tokens, components, and real screens.
Assess naming, variants, states, themes, responsive behavior, accessibility,
composition, content, agentic patterns, and decision provenance.

Distinguish:

- documentation drift;
- implementation bypass;
- missing system capability;
- obsolete system rule;
- legitimate product exception.

Prioritize findings by user/system impact and propose a sequenced migration.
Do not “fix consistency” by flattening purposeful product differences.
