# Self-improvement loop

## Purpose

Continuously learn from meaningful ecosystem changes without letting internet
content or an autonomous agent silently redefine the trusted harness.

```text
OBSERVE → VERIFY → DEDUPLICATE → SCORE → PROPOSE
→ ISOLATED TRIAL → EVALUATE → ADOPT / REJECT / DEFER → RECORD
```

Research is autonomous. Trust expansion and adoption are gated.

This ecosystem loop is distinct from outcome-driven harness evolution. When
sanitized project evidence suggests that instructions, examples, memory
curation, or routing should change, use `./agentic evolve` and the protected
incumbent-versus-candidate contract in
`docs/30-engineering/HARNESS_EVOLUTION.md`. The research loop may discover an
idea; it cannot manufacture product outcome evidence for it.

## Daily scope

Monitor material changes in agentic engineering, orchestration, Claude Code,
Codex, MCP, skills, hooks, context persistence, product design, agentic UX,
design systems, DTCG tokens, frontend/mobile, evaluation, browser automation,
crawling, security, GitHub collaboration, and active project frameworks.

Start with official release notes, specifications, repositories, and known
high-signal sources. Expand only when a material question requires it.

## Evidence hierarchy

1. Standards/specifications.
2. Official documentation and release notes.
3. First-party repositories and source.
4. Original research or first-party engineering posts.
5. Strong independent analysis.
6. Community discussion as a signal.

Record the event date separately from publication or discovery date.

## Finding lifecycle

| State | Meaning |
|---|---|
| `observed` | Potential signal; not verified |
| `verified` | Supported by authoritative evidence |
| `watching` | Relevant but immature or insufficiently useful |
| `proposed` | Concrete change with acceptance criteria |
| `trial` | Reversible experiment on an isolated branch/worktree |
| `accepted` | Verified and approved through normal review |
| `rejected` | Evaluation did not justify adoption |
| `deferred` | Valuable but not currently relevant |

## Scoring

Score 1–5 with rationale for repository relevance, source authority,
confidence, expected impact, adoption risk, maintenance burden, and novelty.
Popularity and stars are not evidence.

## Daily output

Append only material, deduplicated findings to `LEARNING_LEDGER.md`. A run may
correctly report “no material changes.”

An actionable proposal includes evidence, affected source-of-truth files,
non-goals, security/trust impact, acceptance criteria, verification, rollback,
and the required human decision.

## Autonomy boundaries

Allowed: read-only research, comparison, deduplication, ledger updates,
proposals, reversible short-lived branches, and in-scope tests.

Human approval remains required for third-party installation/enabling,
credentials, permissions, secrets, billing, external writes, production,
security/test/review gate changes, and merge.

Never execute code copied from research sources merely to inspect it. Never let
one agent research, implement, evaluate, approve, and merge the same change.
The loop optimizes for sustained quality, not maximum change frequency.

Neither loop trains model weights, deploys, canaries, promotes, or treats a
passing evaluation as merge authority.
