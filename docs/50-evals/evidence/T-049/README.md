# T-049 — Product-specific creative sprint evidence

Status: implementation and deterministic checks pass. Independent product and
design review, human task approval, and newcomer measurement remain separate.

## Observed gap

The starter documented a sophisticated design process but a fresh custom
project still ended with an empty candidate catalog and a generic assistant
prompt. Older generated projects could approve one of the starter's three demo
styles without producing a product-specific composition or interaction. The
governance was strong; the creative production loop was not executable.

## Verified locally

- A fresh design-critical web project exposes `./agentic design sprint` as its
  one next action in terminal output, generated README, handoff, and workspace.
- The sprint carries forward the saved audience, promise, and first useful
  outcome and asks only unresolved consequential questions.
- Three candidates are required by default. Each needs a distinct named
  experiential axis, at least three realistic states, a product-specific
  signature, asset strategy, motion rationale, responsive strategy, and
  reduced-motion behavior.
- Candidate registration fails for duplicate axes, unsafe preview paths,
  missing source files, non-UI preview sources, starter demo surfaces, and fewer
  than three states.
- The generated workspace is explicit that it is not a finished product or
  approved identity, offers one primary copyable sprint command, and renders
  registered live previews side by side with their rationale.
- Generated README, execution handoff, tooling handoff, design-direction brief,
  and `./agentic next` output agree on the same continuation. Reference and
  non-web profiles keep their own appropriate handoff rather than being forced
  through the web sprint.
- Live candidate iframes permit scripts and forms without receiving same-origin
  access to the parent workspace.
- The primary copy action reports success. The fresh workspace has no horizontal
  overflow at a 390 × 844 viewport.
- The complete 252-test repository suite, nine web contract tests, ten-stage
  full verification, production web build, 25 interaction/accessibility browser
  checks, and 24 existing desktop/mobile visual comparisons pass. No visual
  baseline was updated.

## Authority and installation boundaries

The reviewed external prototype skill is preferred only when it is already
installed for a fresh custom or existing-brand sprint. The local skill is a
complete fallback. Nothing installs or invokes an external pack, coding client,
plugin, MCP server, credential, design-tool connection, service, or deployment
automatically. Candidate approval, token compilation, production implementation,
independent evaluation, task approval, and merge remain distinct human-gated
steps.

## Not claimed

The checks do not prove that every assistant run will produce excellent design,
that the current reference identity suits a user's product, that a human has
approved any generated candidate, or that a newcomer can finish unaided. Native
mobile motion and real design-tool round trips are also not certified here.
Those require independent review and the consented P1–P5 pilot rather than a
builder assertion.
